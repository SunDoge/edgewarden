# Web localization

The web app uses Paraglide with English (`en`) as its default language and
Simplified Chinese (`zh-CN`) as an explicit user preference. The preference is
stored locally in the browser; it does not change account or server settings.

## Current coverage

- Login page, including device approval, passkey, and two-step verification UI
- Demo indicator and dialog
- Vault sidebar, header, and mobile navigation
- Theme controls and network status

Business pages, registration/recovery flows, and messages originating from API
responses or shared services are not fully translated yet. This is an incremental
migration, not full-site English coverage.

## Adding messages

1. Add the same semantic key to `apps/web/messages/en.json` and `zh-CN.json`.
2. Keep interpolation names identical in both catalogs; do not concatenate
   translated sentence fragments.
3. Run `pnpm --filter @edgewarden/web i18n:compile` to regenerate message types.
4. Use `m.message_key()` in templates and `$derived` values. Do not evaluate UI
   messages once in static arrays: they must update when the language changes.
5. Run web tests and type checks. The catalog test checks key/placeholder parity.

Generated files in `src/lib/paraglide` must not be edited or committed. The CLI
and Vite compiler configurations must keep the same locale strategy.

## Switching without reloading

The web app is client-rendered (`ssr=false`) and holds unlocked vault keys in
memory. `src/lib/i18n/locale.svelte.ts` supplies a reactive Paraglide locale getter
and changes language without reloading or remounting the app. This preserves
unsubmitted form values and the unlocked session. If browser storage is blocked,
the language still changes for the current session but cannot be remembered.

If SSR or locale-prefixed routing is introduced, revisit this client-only adapter
rather than sharing its mutable locale across server requests.
